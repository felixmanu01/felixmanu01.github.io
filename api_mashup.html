API Mashup

Gig Radar Stockholm.

En paper prototype för en tjänst som kombinerar två olika API källor. Målet är att hjälpa en användare hitta en konsert och direkt förstå mer om artisten innan ett beslut tas.

01

Problemet

Konsertlistor berättar ofta vad som händer och när, men ger mindre hjälp till den som inte redan känner till artisten.

02

Idén

Kombinera information om kommande konserter med artistinformation i samma upplevelse.

03

Värdet

Användaren kan gå från upptäckt till förståelse utan att själv söka på flera olika tjänster.

01

De två API källorna.

Ticketmaster Discovery API

Det första API:t används för att hitta evenemang. Det kan söka efter events och innehåller information om bland annat datum, plats, artist och länk till evenemanget.

MusicBrainz API

Det andra API:t används för att söka efter artisten som hittades i konsertdatan. MusicBrainz kan ge metadata som artisttyp, ursprungsland, taggar och andra identifierande uppgifter.

04

Varför det är en mashup.

En mashup betyder att två separata datakällor kombineras för att skapa något som ingen av källorna ger på egen hand.

Ticketmaster svarar på frågan vad händer och var. MusicBrainz svarar på frågan vem är artisten. Gig Radar kombinerar svaren till en enda användarupplevelse.

05

Vad jag lärde mig.

API data behöver kopplas ihop

Två API källor blir inte automatiskt en mashup. Det krävs ett gemensamt värde. Här är artistnamnet länken mellan eventet i Ticketmaster och artisten i MusicBrainz.

Prototyp före kod

Paper prototypen gör det möjligt att testa idén och informationsflödet innan tid läggs på att bygga en fungerande webbapp.

Datakvalitet spelar roll

Samma artistnamn kan skrivas på olika sätt. En riktig version behöver därför kontrollera att rätt artist matchas mellan källorna.

API källorna har olika ansvar

Ticketmaster används för evenemang. MusicBrainz används för artistmetadata. Varje källa gör en tydlig del av jobbet.
