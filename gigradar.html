Case 03 · Data and API Experiment

Gig Radar Stockholm.

Gig Radar combines scraped concert data from Debaser with live music data from two external APIs. The project explores how different data sources can be combined to identify artist discovery signals and create a stronger foundation for marketing decisions.

The research score is an experimental signal created for this case. A higher value means the artist was less consistently identified across the two external services. It is intended to prioritise further research rather than predict ticket sales or campaign performance.

Method

How it works.

Scraped source

A Node script collects public concert information from Debaser and saves the result as a text file inside the portfolio project.

scraping/scraped_data.txt

API mashup

Artist names from the scraped dataset are searched through MusicBrainz and iTunes. The results are then combined with the original concert information in the browser.

Debaser data + MusicBrainz + iTunes

Business question

The experiment explores whether external discovery signals can make a large concert list easier to prioritise before deeper audience and campaign research begins.

Measurement

The page sends custom events to the data layer when an analysis starts and when it finishes. These events can be configured manually in Google Tag Manager and analysed in GA4.
